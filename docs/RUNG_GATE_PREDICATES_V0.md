## Predicate state

Every required predicate evaluates to exactly one state:

```text
TRUE | FALSE | UNRESOLVED
```

- `TRUE` records that the defined predicate check passed.
- `FALSE` records a defined failure and may issue the mapped counter-receipt.
- `UNRESOLVED` forces HOLD and may issue the mapped counter-receipt after additional examination.

No predicate state creates authority.

## Three-list evaluation

For every target receipt:

```text
satisfied_predicates
unresolved_predicates
failed_predicates
```

Rules:

1. Every required predicate appears in exactly one list.
2. The lists are mutually exclusive.
3. Any `FALSE` predicate appears in `failed_predicates`.
4. Any `UNRESOLVED` predicate appears in `unresolved_predicates`.
5. A predicate may move lists only through a new receipt; old receipt bytes remain immutable.

## Disposition precedence

```text
ANY_FAILED_REQUIRED_PREDICATE
→ REJECT_INVALID

NO_FAILED_REQUIRED_PREDICATES
+ ANY_UNRESOLVED_REQUIRED_PREDICATE
→ HOLD

ALL_REQUIRED_PREDICATES_TRUE
+ PKT_COUNTER_RECEIPTS_NONE = TRUE
→ ACCEPT_AS_INPUT
```
