# Jason’s Accountability Replay Machine V0

**Recall phrase:** `Jason’s Accountability Replay Machine — ask it, source it, challenge it, reverse it, receipt it.`  
**Completion rule:** `NO_RECEIPT -> NO_RENDER`  
**Authority:** `FALSE`

## Purpose

Reusable public-claim verification umbrella. It coordinates existing receipt, challenge, replay, burden-of-proof, and authority-boundary machinery without creating legal, political, journalistic, or governmental authority.

## Core pipeline

```text
CLAIM
→ ASK
→ SOURCE
→ CHALLENGE
→ GAP
→ HOLD / CLOSE
→ REVERSAL
→ DEFENSE
→ RECEIPT
→ PASS?
   ├─ NO  → NO IMAGE
   └─ YES → RENDER IMAGE
```

## Engines

```text
ENGINE_1 = JASON_WISDOM_JOURNALISM
```

```text
EXPERIENCE

```

`NONE_PROVE_THE_NEXT = TRUE`

## Render Receipt Gate

```text
RENDERED_IMAGE = PIPELINE_COMPLETED
RENDERED_IMAGE != PROOF
RENDERED_IMAGE != AUTHORITY
RENDERED_IMAGE != SOURCE
PROOF = UNDERLYING_RECEIPTS_ONLY
IMAGE = VISIBLE_COMPLETION_SIGNAL_ONLY
```

A rendered completion image may appear only after the required claim-specific receipt gates close. A packet may partially close: a proven subclaim may be renderable while a broader unresolved claim remains blocked.

## Result states

```text
PROVEN
HOLD
CONFLICT
FAILED
```

A status applies to the exact claim under test. It must not be silently inherited by a broader claim.

## Split-claim discipline

```text
CLAIM_A = independently testable statement
CLAIM_B = broader or causal statement

CLAIM_A_PASS does not imply CLAIM_B_PASS.
CLAIM_B_HOLD does not erase CLAIM_A_PROVEN.
```

## House rule

> No receipt, no render.

The render is a completion receipt for the pipeline. The proof remains in the underlying primary-source and provenance receipts.
