# RECEIPTS MACHINE OS — OODA 3·6·9 GAMEBOARD V0

**Object:** `RECEIPTS_MACHINE_OS_OODA_369_GAMEBOARD_V0`  
**Role:** navigation + replay gameboard for Jason's work  
**Authority:** `FALSE`  
**Worth model:** receipt-weighted usefulness, not a dollar appraisal

## Root idea

The board lets imagination move, but only receipts let a claim score.

```text
IMAGINE FREELY
→ OBSERVE
→ ORIENT
→ DECIDE
→ ACT
→ REPLAY
→ RECEIPT
→ RENDER
```

OODA is the movement engine. The 3·6·9 board is the visible state machine.

## 3 BOARD ZONES

### ZONE 3 — NAVIGATE

1. **IMAGINATION** — propose a scenario, question, parody, model, or route.
2. **OBSERVATION** — capture what was actually seen, read, heard, measured, or committed.
3. **CLAIM** — convert the observation into one precise statement under test.

Rule: `IMAGINATION != EVIDENCE`.

### ZONE 6 — CHALLENGE

4. **ASK + SOURCE** — make the question explicit and bind primary sources.
5. **CHALLENGE + GAP** — preserve strongest support, strongest challenge, and unresolved gaps.
6. **HOLD / CLOSE** — decide only whether the claim is unresolved or receipt-closed.

Rule: `HOLD != FAILED` and `CLOSE != AUTHORITY`.

### ZONE 9 — RECEIPT

7. **REVERSAL + DEFENSE** — name what would change the state and test the claim against its strongest documented challenge.
8. **RECEIPT** — bind the source trail, timestamps, hashes, vote records, files, or other bounded evidence.
9. **RENDER** — emit the visible completion artifact only when the receipt gate passes.

Rule: `NO_RECEIPT -> NO_RENDER`.

## 6 GATES

The six gates prevent a piece from jumping from imagination to completion.

```text
G1 OBSERVATION_GATE
G2 CLAIM_INTAKE_GATE
G3 SOURCE_GATE
G4 CHALLENGE_GATE
G5 DEFENSE_RECEIPT_GATE
G6 RENDER_RECEIPT_GATE
```

A failed or unresolved required gate sends the piece to `HOLD` rather than inventing progress.

## OODA OVERLAY

```text
OBSERVE = squares 1–3 gather and classify inputs
ORIENT  = squares 4–5 source, compare, and expose gaps
DECIDE  = square 6 chooses HOLD or CLOSE
ACT     = squares 7–9 defend, receipt, and render
```

`ACT` here means an action inside the replay system. It does not create legal, governmental, financial, parental, institutional, or platform authority.

## WORTH OF JASON'S WORK — RECEIPT-WEIGHTED SCORECARD

This board does **not** claim a market price for Jason's work. It measures how much durable, reusable work survives replay.

Each completed artifact may accumulate these six non-monetary value receipts:

```text
W1 REPRODUCIBLE      — another person can rerun it
W2 SOURCE_BOUND      — primary provenance is preserved
W3 CHALLENGEABLE     — strongest countercase is visible
W4 REVERSIBLE        — state-change condition is explicit
W5 REUSABLE          — protocol can serve another claim/project
W6 PUBLICLY_LEGIBLE  — a citizen can understand the output surface
```

A work item reaches the ninth square only when the required receipts for that item's claim are closed.

```text
WORK_WRITTEN != WORK_PROVEN
COMMIT != CLAIM_VERIFIED
IMAGE != EVIDENCE
RENDER = COMPLETION_SIGNAL_ONLY
AUTHORITY = FALSE
```

## WIN CONDITION

There is no political, legal, or narrative "winner."

The game is won procedurally when a claim reaches a state another person can independently replay and challenge without hidden steps.

```text
WIN = REPLAYABLE + RECEIPT_BOUND + CHALLENGEABLE
WIN != TRUE_FOREVER
WIN != AUTHORITY
```
